# MVP Support Matrix

The current limits are enforced by the API and parsers where possible. They should be updated with any release that changes parser behavior.

## Windows desktop

| Workflow | Desktop behavior |
| --- | --- |
| Chat import | Native selection of UTF-8 JSON arrays, objects with a conversation array, or JSONL conversation objects. Each selectable conversation needs a stable ID. The app reads up to 1 GiB and limits a single conversation to 32 MiB. Only reviewed selections enter local storage. |
| Directory synchronization | Explicitly authorize a Markdown directory, an Obsidian Vault, or a chat export directory. Chat monitoring starts after selecting a file and saving a conversation list. Files unrelated to that selection and newly appearing conversation IDs are skipped. |
| Obsidian | Read-only import ignores system directories, links, and Life OS exports. Explicit export writes under `LifeOS-Exports` with keep, copy, and overwrite actions. |
| Local data | The app uses the current Windows user and runs after the main window closes. Daily backup keeps 7 copies after a directory is selected. Restores apply the latest local deletion journal and require re-enabling source and provider permissions. |
| Model and OCR | Configure an OpenAI-compatible provider in the app. Windows Credential Manager stores its secret. The installer includes Tesseract with English and Simplified Chinese models. |

The following table records the existing web and CLI limits. The [desktop acceptance checklist](desktop-acceptance.md) tracks the candidate environments and test evidence.

| Input / workflow | Supported | Limit and behavior | Not supported in this MVP |
| --- | --- | --- | --- |
| Agent memory / notes | UTF-8 `.md` and `.markdown` files through CLI or web | 5 MB per file. Markdown headings become separate timeline entries; a `YYYY-MM-DD` in a heading sets the date. Source file and line range are retained. Missing dates stay unknown. | PDF, DOCX, HTML, arbitrary directories outside explicitly selected files, non-UTF-8 input |
| ChatGPT export | UTF-8 JSON through CLI or web | 5 MB per file. Root array or an object containing a `conversations` array. Each conversation uses a `mapping` of message nodes or a `messages` array. Only `user` and `assistant` text is parsed. The user selects conversation IDs locally; only those conversations are uploaded. Message and conversation identifiers are retained. | Direct ChatGPT API access, scraping, unselected conversation upload, audio/video/other binary message extraction, unrecognized JSON layouts |
| Other chat exports | Claude, Gemini, ZCode, DeepSeek harness, WorkBuddy JSON/JSONL or Markdown through the web/CLI | 5 MB per file. Best-effort generic parser accepts common conversation/message shapes, roles (`user`/`human`, `assistant`/`model`), text/content/parts, and timestamps. It retains conversation/message IDs and source locations. JSONL may contain message objects or conversation objects. Unrecognized shapes fail with a readable error. | Provider-specific fidelity beyond common fields, automatic API sync, encrypted archives, conversation selection for generic exports |
| Documents | TXT, Markdown, text-based PDF, and DOCX through the web | 5 MB per file. Markdown uses heading sections with line ranges; TXT is one item with line locations; PDF uses page text and page numbers; DOCX uses paragraphs and paragraph ranges. Files are parsed locally. | Scanned PDFs and OCR, images/audio/video, non-UTF-8 text, arbitrary folders outside explicit selection |
| Calendar ICS | User-selected UTF-8 `.ics` files through the web app | 5 MB and at most 1,000 VEVENTs. Each successful upload is a complete snapshot. UID is the stable event key, SEQUENCE prevents older versions from replacing newer ones, and times normalize to UTC while preserving TZID/all-day/floating metadata. Updates create a new current version; `METHOD:CANCEL`, `STATUS:CANCELLED`, and events missing from a later complete snapshot are soft-removed and journaled against backup restore. The web UI previews event/recurrence counts and can update an existing calendar source. | RRULE/RDATE/EXDATE/RECURRENCE-ID expansion, CalDAV/API sync, URL or attachment fetching, partial snapshots, server-side filesystem access |
| Quick notes | Web Add note form and `POST/PATCH/DELETE /api/v1/quick-notes` | Up to 20,000 characters with optional title and timezone-aware time. Stored as owner-scoped `SourceItem(kind="quick_note")` under a hidden internal source. Generic source pause/resume/revoke/delete/cloud-consent controls reject that internal source; notes are managed through the quick-note API. Notes appear in timeline, unified search, dated reviews, Markdown export, and account archive. Single-note deletion is soft, item-scoped, invalidates linked generated records, and is replayed from the deletion journal after restore. | Separate original-file download, collaborative notes, rich text, silent overwrite of other notes |
| Evidence graph extraction | Manual selection of imported items through the extraction API | Requires source-level cloud consent and a configured OpenAI-compatible provider. Sends only selected item text; validates JSON; creates entities, relations, and bounded evidence with confidence. High-confidence items become active, low-confidence items enter review. Completed identical batches are idempotent; monthly budget warns at 80% and blocks over-budget calls; per-call limit applies. | Full automatic multi-source extraction, semantic/vector extraction, local-only extraction |
| Graph review, merge, and ontology | Web review queue plus graph, merge, and ontology endpoints | Low-confidence entity/relation items can be edited, approved, or rejected individually or in bulk. Entity merges keep aliases and a reversible snapshot; approved custom entity/relation types enter later extraction prompts. All records remain owner-scoped. | Automatic conflict arbitration without review, graph database/ontology reasoning, merge across owners |
| Evidence Q&A | Chinese-first Ask page and question-thread API | Answers locally without a model call from active evidence only. Supports source, project/topic, and date scope; remembers the last scope; returns facts, citations, confidence, fact/inference/uncertain labels, missing information, and action suggestions. Revoked sources, deleted items, and inactive evidence are excluded; with no evidence the answer refuses to fabricate. Threads can be exported as JSON/Markdown or deleted. | Semantic/vector retrieval, cross-owner questions, model-written answers, guaranteed completeness of the graph |
| Rule insights | Graph, Ask, and projects pages plus rule API | Four explainable rules: overdue goals, commitments without follow-up, stalled projects, and skills with weak or stale evidence. Each result lists trigger, evidence, confidence, and a suggestion. False positives can be dismissed and do not repeat. Staleness and skill-evidence thresholds are configurable. | Predictive risk scoring, automatic external notifications, cross-owner insights |
| Agent actions | Agent action API plus in-app notices and undo | Deterministic internal writes for reminders, tasks, projects, growth records, goal progress, and review drafts. Every action stores before/after values, evidence item IDs, and audit metadata, and can be undone for 24 hours. External sending, original-file changes, spending, and deleting data or changing goals are rejected without explicit human approval. | Autonomous external side effects, unattended irreversible transactions, unrestricted filesystem access |
| Local plugins | Plugin catalog, manifest, permission, invoke, and audit APIs; settings UI | Connector and agent-tool manifests declare permissions. Undeclared permissions are denied; lifecycle and invocations are audited; plugin failures are isolated. Reference JSON/JSONL/Markdown connector can preview, import, and delete a user-imported source; reference agent tool searches active graph evidence. | Plugin marketplace, remote execution, third-party signing, strong sandboxing |
| Model providers and consent | Settings page plus `GET /model-providers` and `PUT /model-providers/consent` | The built-in OpenAI-compatible provider uses `MODEL_PROVIDER/OPENAI_*`; named providers use `MODEL_PROVIDERS` JSON with model lists, prices, disclosure text, and optional loopback local endpoints. API keys remain in environment/local config and are omitted from API responses, archives, and logs. Consent is owner + provider + disclosure-version scoped; revoking one provider cancels only its queued/running model jobs. Manual and scheduled reviews persist provider/model selection and revalidate it before worker calls. | Database-stored credentials, remote provider administration, automatic consent inheritance between providers |
| Budget and usage | Settings panel and `GET /api/v1/budget?period=day|week|month` | Reports selected-period and monthly-limit spend, remaining budget, 80% warning, overage, provider/purpose costs, run counts, input/output tokens, average latency, and failure-reserve costs. `ModelRun` remains the archive source of truth. | Provider invoices, multi-currency billing, team budgets |
| Photos | User-selected JPEG/JPG, PNG, or WebP through the web app | Up to 10 photos per selection, including one user-selected folder. Each photo is limited to 20 MB and 40 megapixels by default. The server applies orientation and re-encodes to remove EXIF/GPS metadata. OCR runs inline or as a worker job, depending on `PROCESSING_MODE`; Tesseract extracts English and Simplified Chinese text when installed. OCR may return no text or fail. User-supplied capture time requires a timezone. | HEIC/HEIF, RAW, GIF, video, face recognition, automatic photo-library scanning, guaranteed OCR quality |
| Photo description | Optional OpenAI image description through the web app | Requires provider configuration and current consent. Only the sanitized image is sent; worker mode uses a durable job. Output stays a draft until the user confirms it. | Unrequested automatic descriptions, unconfigured providers, unconditional inference |
| Weekly review | On demand or on a saved weekly schedule in the web app | Uses a selected half-open date range and at most 500 timeline items. Template mode is available without external AI. Optional external output must cite accessible source IDs and falls back on provider failure; worker mode uses a durable job. Draft suggestions can be edited, dismissed, or restored; dismissed suggestions drop out of the rendered review until restored. Scheduled generation uses the user's weekday/time and only active sources; it requires `PROCESSING_MODE=worker`, skips periods with no active items, and falls back to the template when provider consent, configuration, or budget is unavailable. Manual and scheduled reviews can select an environment-backed provider/model. Drafts include deterministic cross-period trends, commitment/due-date extraction, active-goal links, and source-linked facts; unsupported model facts are filtered. Review versions are immutable snapshots with read-only comparison. Due and overdue reminders appear in the sidebar and Weekly review page. | Email/push delivery, guaranteed semantic correctness of model prose |
| Scheduled folder sync | CLI plus Windows Task Scheduler | `lifeos sync <folder> --yes` reuses the source identity and SHA-256 deduplication. `scripts/register-scheduled-sync.ps1` registers a daily task, writes `data/logs/scheduled-sync.log`, and reads only the selected folder. The API must be running, and the project checkout/`uv` must remain available. | Server-side filesystem watching, cross-device sync, provider-hosted scheduling |
| Timeline lookup | Date range, source filter, keyword query | Owner-scoped, paginated, simple case-insensitive SQL `LIKE` search. Undated items can remain visible. | Full-text ranking, semantic/vector retrieval, saved searches |
| Unified search | Timeline items, weekly reviews, and reminders through the Search page | SQLite uses FTS5 trigram; PostgreSQL uses `pg_trgm` GIN when the extension is installed. Short queries, unavailable extensions, and unsupported builds fall back to case-insensitive `LIKE`. Candidates are rechecked for owner, current version, deletion, source status, and filters. Supports result type, half-open user-timezone date range, source, status, tag, and collection filters. Saved searches persist the query and filters per owner. | Semantic/vector retrieval, cross-group relevance scoring, remote search services |
| Tags and collections | Web Organize page plus `/tags`, `/collections`, and `/items/{id}/organization` | Owner-scoped tags use casefold-unique names and optional colors; collections use casefold-unique names and optional descriptions. Associations accept only current, undeleted items belonging to the same owner. Deleting a tag or collection removes associations but not items. Markdown export and account archive include names/IDs. | Shared team tags, automatic tagging, hierarchical collections |
| Markdown and Obsidian export | CLI for timeline records and confirmed reviews; web for individual records/reviews, quick notes, and direct Vault export | UTF-8 Markdown, stable Life OS IDs, source/date metadata, and tag/collection frontmatter. CLI offers keep/overwrite/copy behavior and atomic writes. In Chromium-based browsers with File System Access API, web export writes into a directory selected by the user; keep is the default, copy adds numeric suffixes, overwrite requires explicit selection, and unsupported/permission-denied paths download instead. Same-origin writes use Web Locks; the browser API cannot atomically exclude an external editor race, so close an open note before re-export. Vault frontmatter publishes `lifeos_id`, `title`, `type`, `source`, `occurred_at`, `tags`, `collections`, and `exported_at`. Quick notes use the same stable ID and source metadata without a separate original file. | Silent writes to source files, server-side Vault paths, automatic two-way Obsidian sync |
| Mobile and PWA capture | Installable web app, `/capture`, and browser share target | Standalone manifest, installation icons, offline static shell, mobile-friendly quick-note capture, and text/title/URL sharing through the existing owner-scoped quick-note API. Shared content is held in an ephemeral browser inbox until read. Due reminders remain visible in the mobile layout. Browser notifications require explicit permission and are optional. | Background push delivery, offline note queue, mobile native package, capture of arbitrary files or media |

## Verification fixtures

Photo file and directory selection is available in the web importer. The CLI imports Markdown and ChatGPT JSON, and both interfaces can export a photo timeline entry as Markdown. Deleting an item can remove the shared imported original and other entries created from that original. The web action names the imported source and states that its original file and every entry created from it are removed. Photo-description and weekly review flows have their own confirmation controls. Weekly review suggestions can be edited, dismissed, or restored while the review is a draft; reminder creation uses the edited text, and the rendered review text follows automatic edits unless the user has already rewritten it.

`fixtures/synthetic/` contains fabricated Markdown and ChatGPT exports. It contains no user data. Run:

```powershell
uv run pytest -q
uv run python scripts/evaluate_reviews.py
uv run python scripts/evaluate_search.py
uv run python scripts/evaluate_graph_qa.py
```

`scripts/evaluate_search.py` runs 22 bilingual queries against 10,000 synthetic timeline rows plus reviews and reminders. It defaults to disposable SQLite data and accepts a separate PostgreSQL database through `LIFEOS_BENCHMARK_POSTGRES_URL` when one is available.

Graph coverage lives in `tests/test_graph_model.py`, `tests/test_graph_inputs.py`, `tests/test_graph_extraction.py`, `tests/test_graph_review.py`, and `tests/test_graph_qa.py`: owner scope, source consent/revoke, Claude/Gemini-like JSON, JSONL, TXT/Markdown/DOCX, low-confidence review, idempotent batches, provider routing, budget guard, failure recording, review edits/bulk decisions, merge undo, ontology approval, four question types, scope memory, and revoked/deleted evidence exclusion. Rule insights, agent actions, plugins, and budget are covered by `tests/test_insights.py`, `tests/test_agent_actions.py`, `tests/test_plugins.py`, and `tests/test_budget.py`. `scripts/evaluate_graph_qa.py` runs 30 bilingual questions across decision, project, growth, timeline, revoked, and deleted cases.

M7 coverage lives in `tests/test_calendar_ics.py` and `tests/test_quick_notes.py`: ICS timezone/DST/all-day/floating normalization, complete-snapshot updates, low-SEQUENCE rejection, cancellation/missing-event removal, recurring-rule skips, invalid-snapshot rollback, deletion-journal replay, quick-note CRUD/search/archive, item-scoped deletion, review invalidation, and owner isolation. `web/e2e/workflow.spec.ts` covers ICS preview/update/cancel and quick-note create/edit/search/export/delete in a real browser.

M8 coverage lives in `tests/test_search_organization.py` and `scripts/evaluate_search.py`: FTS5 trigram selection, LIKE fallback for short queries, type/date/source/status/tag/collection filters, saved-search CRUD and owner isolation, tag/collection CRUD and association replacement, archive metadata, stale-index exclusion, and rebuild behavior. The evaluation expands to 31 bilingual queries and compares indexed search with LIKE on the same 10,000-row dataset. Browser coverage includes filtered/saved search and tag/collection creation, association, filtering, export, and editing.

M9 coverage lives in `tests/test_m9_review_intelligence.py`: provider registry secret redaction, per-provider consent, selected model routing, local loopback providers, provider-scoped job cancellation, budget fallback, source-linked insights, cross-period trends, review versions, and archive consistency. `scripts/evaluate_review_models.py` runs the fixed 30-case suite against configured providers; `scripts/serve_review_eval_provider.py` supplies a deterministic loopback baseline. The 2026-11-26 MiniMax + baseline report is stored in `review-model-evaluation.json`.

M10 coverage lives in `web/e2e/m10.spec.ts`: stable frontmatter and filename sanitization, keep/copy/overwrite behavior, preservation of manual edits, permission-denied download fallback, 390×844 capture, real service-worker share handling and inbox deletion, no API caching, and denied-notification fallback. The 2026-11-26 acceptance also opened the exported file in Obsidian 1.15.1, verified tag/collection properties and body rendering, and confirmed a manual edit remained on disk.

`scripts/benchmark_mvp.py` separately measures 30 timeline-query samples against 10,000 synthetic SQLite rows and 30 imports of 500 synthetic Markdown sections. It is a local smoke benchmark, not hosted performance evidence.
