# Personal AI Life OS 开发与迭代方案

基线为 2026-11-24 的 `main`（`7f7156a`）。首个交付目标是让用户选定资料、找到带来源的时间线条目，并把值得保留的内容写入 Obsidian。从合成 `memory.md` 导入起步，依次接通选定的 ChatGPT 对话、Web 时间线与 Markdown 导出。文本流程贯通后，验证用户是否愿意每周回来复盘、确认行动并导出。

排期按一名主要开发者每周投入 4 个有效人日估算，从开工周起算。第 12 周评估文本私测准入，第 14 周评估完整 MVP，第 15–16 周预留给格式兼容、部署和反馈返工。试用门槛、负载与预算数字均为首轮目标，按实际投入和首批测量在每个里程碑重新估算。产品范围依据 [MVP PRD](../product/prd.md)，阶段沿用 [M0–M4](milestones.md)。

## 2. 首批用户与竞争验证

首批面向每周用 AI 做研究、学习或开发，并习惯在 Obsidian 或其他 Markdown 编辑器里整理成果的个人用户。周末复盘围绕本周决定、支撑证据和下周跟进事项展开。现有的手工选材、复制和写周报流程作为测量基线。

| 参考产品 | 已有能力 | Life OS 要验证的体验 |
| --- | --- | --- |
| Obsidian | Vault 由本地 Markdown 文件组成，其他编辑器也能打开。 [Obsidian 帮助](https://obsidian.md/help/data-storage) | 用户可直接打开导出笔记。重复导出后保留用户编辑，来源定位随笔记一起保留 |
| Gemini Notebook（原 NotebookLM） | 可对选定资料问答，并从引文跳到原文位置。 [Google 更名公告](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/) · [引用说明](https://support.google.com/gemininotebook/answer/16179559) | 用户从按周组织的决定和行动直接核对来自聊天与 Markdown 的证据，测量找回证据的时间 |
| Khoj | Obsidian 客户端支持基于笔记的聊天和搜索，另有定时查询。 [Obsidian 客户端](https://docs.khoj.dev/clients/obsidian/) · [定时任务](https://docs.khoj.dev/features/automations/) | 用相同的选定资料衡量从整理证据到确认待办、导出本周复盘的操作时间和人工校正量 |
| Day One | 可按历史上的同一天回看条目和照片。 [On This Day 文档](https://dayoneapp.com/guides/tips-and-tutorials/on-this-day-view/) | 用清楚的时间与来源导航找回工作决策，再将待跟进事项挂到下周 |

文本 Alpha 用同一套两周合成资料做任务对比，包含两类输入、已知决定、日期缺失和重复文件。在文本私测中跟踪同一批用户的连续两周，记录完成时间、找到的证据比例、手工返工与下一周复用情况。优先把试用反馈投入最慢、失败最多或最影响回访的环节。产品差异来自跨来源的复盘和可携带的输出，这一假设由试用结果验证。

主路径约 41–55 人日，加机动约 48–63 人日。工作依赖为工程基线 → 所有者与持久化 → 可重试导入 → 时间线与导出 → 复盘 → 托管私测。照片处理复用同一导入、引用与删除链路，在文本闭环稳定后交付。第 12 周跑通准入后即可发起文本私测，连续两周的产品信号要等第 14 周或之后复核。

相对现有里程碑，首次持久化加入租户边界，单条 Obsidian 导出提前到 M2a，周报导出留在 M3。照片仍纳入完整 MVP，按 M2b 独立验收。全文索引增强、向量检索和可配置模型列表按 P1 处理。完整 MVP 同时覆盖 PRD 的本地选源、增量导入、时间线、可编辑 AI 草稿、按需周复盘、应用内提醒、Markdown 和账号归档、暂停/恢复、断开及删除。定时上传、自动送达、更多连接器、移动端和团队空间进入后续评审。

## 4. 实现约定

### 导入与数据边界

- **预览与最小上传。** CLI 接受明确选定的文件或目录，展示文件、体积、类别和将要提交的内容范围。预览在本机计算哈希，确认后复核文件是否变化。ChatGPT 导出在本机读取，用户选定对话后提交相应记录，保留会话/消息标识和来源定位。支持的 JSON 结构以合成 fixtures 和实际兼容验证为准，未知结构返回说明。首版可让用户先在本机解压并选文件。 [OpenAI 导出说明](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)
- **原件、版本与日期。** `SourceItem` 保留实际接收资料的不可变版本、来源、SHA-256、发生时间、导入时间及解析器版本。Markdown 引用用文件版本、标题和行范围，聊天引用用会话、消息及本地投影定位。日期缺失时单独展示，已知时间按 UTC 保存并按用户时区划分周，保留来源时区信息或明确标注未知。
- **幂等、并发与重试。** 用所有者、来源、稳定外部标识和内容哈希约束原件版本，区分重复提交和同一资料的更新。解析按输入版本与解析器版本幂等执行。同步任务记录待处理、处理中、完成、部分失败、失败及取消等状态，提供结构化错误和逐项结果。异步化时确保任务可从已提交的工作记录恢复，重试只重做可恢复的失败项，暂停或撤权后阻止新任务和未获授权的派生写入。
- **鉴权与删除。** 服务端从可信身份获得所有者，数据库关系防止跨所有者串联，列表、来源读取、导出和后台任务都按所有者校验。私测默认由受鉴权的下载端点访问对象，每次检查权限和删除状态，存储签名地址留在服务端。删除入口先阻断读取、下载与重试，再清理原件、解析内容、索引、引用和派生数据，并公开完成状态。仅依赖已删资料的生成条目删除，多来源条目在重算期间暂停展示。含已删证据的旧生成周报从在线访问中移除，提示用户重新生成。导出到用户设备的副本由用户管理。
- **处理与存储。** 在现有 FastAPI 上引入路线图中的 SQLAlchemy、Alembic 和 PostgreSQL。开发使用本地对象适配器，托管阶段使用私有对象存储。首个有体积上限的合成演示可直接解析。大文件、OCR 或模型任务使用可恢复的 worker，启用 Redis 队列时由数据库记录权威任务状态。索引起步用所有者、日期和来源筛选以及有边界的关键词匹配，按真实查询评估中文和英文表现。

### Web、复盘与导出

- **最小接口契约。** 保留 `/api/v1/health` 作为存活检查。数据库接入后增加就绪检查。先定义来源、上传任务、条目/来源、时间线与删除接口，随后定义复盘草稿、确认、提醒和归档。接口记录分页顺序、时间格式、重试语义和稳定错误码。前端覆盖加载、空态、失败、已撤权和无权限访问场景，主要操作支持键盘。
- **可核对的周复盘。** 用用户时区与半开日期区间收集已确认条目，输出事实、建议和待办草案。生成的事实须引用本次输入中可访问的来源，服务端校验引用是否合法，人工抽样判断是否支持事实。草稿与确认稿有独立状态，标明用户补充内容，旧版本可按数据保留规则追溯。含义不明确时提示用户确认。生成任务无权限执行原文里的指令或发出外部操作。提醒仅在用户确认后创建。
- **模型的同意与回退。** 先接一个可替换的提供方，使用结构化输出、合成评估集、超时与成本上限。调用前展示提供方、字段与保留条款，用户选择模板复盘时仍能完成主流程。记录模型、提示词版本、耗时和用量，日志仅写阶段、错误码等操作元数据。
- **便携与冲突控制。** 导出采用 UTF-8 Markdown、稳定文件名和 frontmatter ID，附可独立阅读的来源标签、日期和定位符。敏感正文引用按明确选择导出。CLI 先预览目标目录和写入差异，比较已生成内容的指纹，遇到用户编辑时提示保留、另存或显式覆盖。用原子写入并验证目标在所选目录内。账号归档交付 Markdown 与 JSON 清单，带授权允许的原件及关联索引。
- **照片。** 预览明确上传的是去除位置等非必要元数据的副本，保留用户选择的拍摄日期字段及来源引用。缺拍摄时间时可由用户补充或标注未知。OCR 文本可检索并区分自动提取与用户笔记，外部图像描述沿用单独的模型告知。

## 6. 验收、发布与故障处理

### 进入真实资料文本私测的条件

1. 在共享环境验证 Web 登录、CLI 授权、私有对象读取和后台任务鉴权。双账号验证来源、对象、搜索、复盘、提醒、归档和删除，覆盖未登录、错所有者、撤权和暂停。复用已取得的下载链接验证删除后不可读取。所有隔离与删除用例须通过。
2. 演练单条、整项来源和账号删除，覆盖衍生内容、索引、对象、排队任务、在途任务与恢复流程。活跃系统先阻断访问，设定并实测清理目标（首轮拟定 24 小时内完成）。上线前公布备份过期窗口并验证恢复后重放删除记录。用私有对象存储、TLS、托管密钥、静态加密和内容脱敏配置运行。
3. 对合成资料执行一次完整体验，从选源、导入、核对来源到编辑周报、确认提醒、Obsidian 导出、账号归档和删除。缺失文件、重复提交、解析失败、队列重试、模型不可用与冲突写入都有可理解的处理结果。支持矩阵与部署运行手册随版本交付。
4. 在托管环境打开导入失败率、积压、删除延迟、接口错误率和模型预算面板，演练暂停上传或推理、修复后恢复。发现跨账号读取、私有内容暴露、不可恢复数据损坏或无法完成删除的缺陷时，停止扩容并阻断相关入口，待修复、影响确认和复测后再恢复。

### 初始质量与价值指标

| 指标 | 首轮目标和口径 | 未达标时的安排 |
| --- | --- | --- |
| 首次价值 | 首批至少 5 名完成入组的用户中，≥80% 无人代操作完成选源导入、核对首条引用并导出，成功者中位用时 ≤5 分钟。从打开引导到首份导出，使用预先准备的资料，外部申请导出等待单独记录 | 复看完成录屏或访谈记录，优先修复最早的卡点 |
| 每周复用 | 至少 5 名入组满两周的用户中，≥60% 在连续两周各保存一次复盘。对有配对数据的参与者，分别计算第二周产品用时较本人手工基线的降幅，取中位数，目标 ≥30%。公布回访指标的分子和分母、配对样本数和放弃情况 | 分析未返回、未保存与手工返工三类原因，下轮只扩大一项已验证需求 |
| 导入与延迟 | 固定合成批次上重复/并发导入的重复条目数为 0。私测环境对输入 ≤5 MB 且 ≤500 条的文本批次测至少 30 次，提交到首批可见的 P95 ≤30 秒。用 1 万条测试记录和固定查询样例测常用时间线/来源查询，服务端 P95 ≤500 毫秒 | 用解析、排队、写库或查询耗时定位瓶颈，外部模型耗时独立统计 |
| 引用与复盘 | ≥30 个合成场景覆盖冲突、资料不足、时区、重复和模型故障。生成事实的来源可定位率 100%，人工检查的引用支持率 ≥95%，关键决定、负责人或日期的严重无据断言为 0 | 拦截无效引用，减少输入范围或收紧模板，再跑同一评估集 |
| 数据与模型成本 | 双账号、撤权、删除及导出冲突发布用例全部通过。按模型调用计量耗时、令牌和单次成本。拟以每次成功周复盘草稿 0.10 美元为成本上限（分子计入失败与重试费用），选定提供方后用固定评估集校准 | 数据控制缺陷阻断发布。触及模型预算时关闭外部推理，使用模板复盘 |

每次验收在 PR 或发布记录附上版本、配置、测试数据规模和结果。行为指标用经同意的事件或访谈记录采集，保留阶段和耗时，省去聊天、照片和笔记正文。小样本用于定位工作流问题，后续扩大样本时重新测试阈值。

## 7. 迭代节奏与决策记录

- **每周排期。** 维护者按主路径安排下一周，保留一项主要交付，记录完成证据、阻塞和实际人日。每两周用同一合成数据演示一次，并对比目标、结果与下轮改动。范围变化通过 Issue 记录理由、依赖、验收和影响的发布目标。
- **合并与变更。** PR 附可复现的验证命令、失败行为与兼容影响。每次迁移先在空库及前一版本数据上跑升级，涉及迁移或删除时用合成快照演练恢复。接口、导入格式和前置依赖变化随版本写入文档。
- **发布。** 通过发布条件后先在托管测试环境跑合成端到端，再对邀请组启用。版本化镜像、迁移与配置，先确认旧应用版本能读取新 schema 再回退应用。保留恢复路径并复核被删除记录在备份恢复后的状态。
- **反馈排序。** 私测每周回顾失败、时间花费、手工更正、来源使用和用户反馈。先处理数据访问/删除、导入或引用可靠性，再用观察结果改善首用和复用。扩展搜索由检索任务失败和延迟推动，增加连接器由用户实际来源分布推动，定时复盘由连续复用及主动需求推动。

| 待定决策 | 锁定时间与责任 | 所需证据和默认推进方式 |
| --- | --- | --- |
| 首版数据契约和支持格式 | M0–M1 · 后端与维护者 | 依据合成 fixtures 写明文件上限、来源定位、去重冲突和版本兼容。先落实一类 Markdown 和经过验证的一类聊天结构 |
| 托管鉴权、对象存储和备份保留 | M2 完成前评估，M4 上线前由维护者锁定 | 试验 Web/CLI 登录、对象撤权及备份删除演练。没有合格配置时继续运行合成环境 |
| 模型提供方和费用额度 | M3 接外部推理前 · 产品与维护者 | 用固定评估集对比引用、延迟、成本和保留条款。模板复盘可独立运行 |
| 照片配置与兼容 | M2b 开始前 · 产品与维护者 | 用合成图片验证 OCR、位置字段处理与支持矩阵，优先选能覆盖首批试用设备的格式 |

## 8. MVP 后的迭代选择

完整 MVP 验收后按两周一个周期排期。首轮先复核私测的首次使用、两周复用和引用质量。门槛未达时，优先修复最影响该指标的一步并用原任务复测。达标后，从下表选择证据最充分的一项做两周试验，按改善幅度和维护成本决定是否扩大。

| 候选 | 启动证据 | 两周试验的验收 |
| --- | --- | --- |
| 增强检索 | 反复出现用户知道资料已导入却找不到的查询 | 从用户授权的反馈抽象出中英文查询样例，比较关键词基线和全文/向量候选。用前 5 个结果的命中率、查询延迟和删除一致性选型 |
| 新连接器 | 至少 3 位试用用户的同类资料在现有流程中需要反复手工整理 | 只完成一个来源的预览、增量导入、引用定位和删除。用同一类型样例测手工整理时间是否下降 |
| 定时复盘 | 至少 3 位已连续保存两周复盘的用户主动要求准时送达 | 对愿意试用的人开放时区、自选时间和关闭开关。至少跨过两个周期，核对准时率、重复送达和撤回后停发情况 |

继续维护可公开复现的合成演示、格式支持矩阵和评测记录。每次发布展示一项端到端改进及其前后结果，便于试用者和贡献者复核。
