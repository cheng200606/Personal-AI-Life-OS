- **MVP 的本地主链已基本完成。** 导入、时间线、照片 OCR、周复盘、提醒、导出、删除、备份恢复、统一检索都有实现和合成验收。

- **v0.5 新增的证据图谱、待审治理、实体合并、自定义本体、个人问答、规则洞察、Agent 行动、插件 SDK 与中文优先界面已实现**；这些新增能力未计入原 51 项分母。
- **Windows 桌面（D0–D5）已于 2026-11-27 完成本机候选验收。** 桌面 9 项能力中 7 项完成、1 项部分完成（Windows CI）、1 项为当前范围非目标（签名自动更新）；详见 5.9、[桌面 MVP 迭代](desktop-mvp.md) 与 [桌面本地验收](../operations/desktop-acceptance.md)。
- **PRD P0 的本地功能已覆盖；P1 五项中，统一检索、定时复盘、多提供方与移动捕获/通知已交付，更多连接器仍为部分实现。**

## 2. 评估口径

### 2.1 目标基线

“最终产品”分为三层，本文以第二层为主要评分对象：

1. **MVP（P0）**：单人本地可用的导入、时间线、复盘、提醒、导出、数据控制。当前视为完成。
2. **文档设想的完整产品（P1 与后续候选）**：定时同步/复盘、更多连接器、增强检索、可配置模型、移动捕获与通知，以及全文/向量检索、标签、跨周期洞察、直接 Obsidian 写入、托管多用户等。
3. **超出当前文档的扩展**：AI 对话式问答、团队共享、插件生态、国际化等。本文只列为远期方向，不计入主评分。

### 2.2 状态定义

- **完成**：有实现、测试或验收记录，用户入口可用。
- **部分**：有可用的子集，但缺少文档承诺的关键部分。
- **未开始**：没有实现或只有模板/文档。
- **非目标/暂缓**：当前单人本地范围明确不追求，或文档列为永久非目标。

### 2.3 量化方法

按能力项计数，不以代码行数或页面数量代替。本文自 2026-11-27 起只报告「完成/部分/未开始/非目标」计数；早期版本曾用加权百分比，但分母与分项合计不可复核，已停止使用。

## 6. 开发方案

### 6.1 原则

- **单人本地优先。** 不为未见过的多用户需求增加托管复杂度；托管路径保留但不上线。
- **每次迭代交付一个端到端闭环。** 不做只有后端或只有界面的半成品。
- **不改变数据控制不变量。** 所有者隔离、删除不可复活、来源引用可追溯、外部调用需同意与预算，必须随每个功能补测。
- **先测量再扩容。** 检索用固定查询集，性能用固定数据规模，AI 用固定评估集；没有证据就不引入新基础设施。
- **不新增依赖，除非现有栈无法完成。** 优先复用 SQLAlchemy、worker、现有模型网关。

### 6.4 M7 连接器与快速捕获

**状态：** 2026-11-26 已完成。Ruff、117 项 Python 测试、Web lint/生产构建与 7 项 Playwright 通过；Alembic 空库升级到 `e8c4f2a7b913`、降级回 `d7f1a3b5c902` 再升级且 `alembic check` 无漂移。ICS 与快速笔记均为本地合成数据验收，不代表真实日历规模或托管 PostgreSQL 性能。

**目标：** 减少手工复制，先接通一个高价值、无外部密钥的来源，并让用户直接记录笔记。

**数据契约：**

1. **ICS 完整快照。** 新来源 `calendar_ics` 只接受用户上传的 UTF-8 `.ics` 文件，每次成功上传视为该来源的完整快照。Web 可选择更新现有日历来源，避免同一文件跨来源重复。
2. **事件身份与版本。** `UID` 是稳定事件键，`SEQUENCE` 是单调版本号；改期不改变身份，低序号上传不得回退当前事件。开始/结束时间统一保存为 UTC，同时保留原始 TZID、浮空时间标记和来源定位。
3. **取消与缺失。** `METHOD:CANCEL` 或 `STATUS:CANCELLED` 使现有事件软撤销；完整快照中消失的事件同样软撤销。软撤销事件立即退出时间线、统一搜索和复盘，但不物理删除历史版本。
4. **重复规则边界。** 首版只处理单次日程和全天日程，不展开 `RRULE`/`RDATE`/`EXDATE`。预览与导入结果明确报告跳过数量，不静默丢弃。
5. **快速笔记表示。** 用户笔记以 `SourceItem(kind="quick_note")` 为唯一正文，归属一个内部 `quick_note` 来源；普通来源列表隐藏该内部来源，通用来源管理接口拒绝直接暂停、撤权、删除或配置云端同意。笔记可编辑，编辑后重算内容哈希，并立即进入时间线、搜索、复盘与 Markdown 导出。
6. **删除粒度。** 导入条目的“删一条即删整个来源”语义不变；快速笔记只软删除当前条目，并使相关复盘、记忆记录和提醒引用失效，不删除其他笔记。
7. **边界与审计。** 上传上限 5 MB、最多 1,000 个 VEVENT，并限制属性与文本长度；不抓取 URL、附件或读取服务器路径。`SyncRun` 记录新增、更新、重复、撤销与跳过数量，失败不改变现有快照。

**接口与交付：**

- 复用 `POST /api/v1/sources/{source_id}/imports` 完成 ICS 解析、版本替换和快照对账。
- 新增 `POST /api/v1/quick-notes`、`PATCH /api/v1/quick-notes/{id}`、`DELETE /api/v1/quick-notes/{id}`。
- Web 增加 ICS 本地预览、更新现有来源、Add note 编辑与单条删除。
- 支持矩阵、隐私说明、README、架构与里程碑记录实际边界。

**验收：** 同一 ICS 重复导入无重复；改期只保留新当前版本；取消/缺失事件不可召回；旧序号不回退；快速笔记可创建、编辑、搜索、导出、删除；无跨所有者结果；全链路无外部网络调用。

**执行记录：**

- 新增 `parsers/calendar_ics.py` 与 `icalendar` 锁定依赖，覆盖 UTC/IANA/全天/浮空时间、DST 歧义与不存在时间、事件上限和重复规则跳过。
- 新增 ICS 完整快照对账、来源行锁、UID/SEQUENCE 版本控制、取消/缺失软撤销、旧版防回退和失败不改动当前快照。

**数据契约：**

- 每条 Vault 文档使用稳定 Life OS ID，并发布 `lifeos_id`、`title`、`type`、`source`、`occurred_at`、`tags`、`collections`、`exported_at` frontmatter；条目保留 `source_locator`，复盘保留 `source_ids`、周期、状态与版本，未知日期不伪造。
- 文件名由标题归一化生成，移除路径分隔符与控制字符并限制长度；不使用服务端任意路径。
- 冲突默认 `keep`；`copy` 递增 `-1`、`-2` 后缀；只有用户明确选择 `overwrite` 才替换。重复导出不静默覆盖用户在 Obsidian 中的修改。
- Vault 目录授权不持久化到服务端，也不写入账号归档；每次写入都由浏览器内的显式用户动作触发。
- PWA 分享目标只接收 `title`（200 字符）、`text`（20,000 字符）、`url`（2,000 字符），按既有快速笔记上限截断；收件箱 15 分钟过期，在捕获页读取后或退出登录时删除。
- 通知授权状态由浏览器保存；未授权、拒绝或 Service Worker 不可用时，到期徽标与 Due now 面板继续工作。

**交付：**

- **直接写 Vault。** Web 使用 File System Access API 选择目录并写入带 frontmatter 的 Markdown；冲突策略明确，浏览器不支持时回退下载；发布字段与标签语义。
- **移动/PWA。** 增加 manifest、安装图标、应用壳、分享目标与移动友好捕获页；应用内到期提醒在移动布局可见。
- **通知。** 显式授权浏览器通知，可展示当前到期数量并点击回应用；失败与拒绝均有可理解反馈。
- **测试。** 冲突写入、frontmatter/标签、移动视口、分享目标、通知拒绝、无权限回退；不静默覆盖。

**验收：** 导出文件在 Obsidian 中正常打开；用户手改后重复导出默认保留修改；移动端可完成一次捕获与查看；分享文本进入捕获页且读取后清除；无静默覆盖。


**执行记录：**

- 新增 `web/src/vaultExport.ts` 与 `web/src/markdownExport.ts`，统一 frontmatter、文件名清理、keep/copy/overwrite 与下载回退；时间线、快速笔记和复盘导出均接入。
- 新增 manifest、192/512 图标、Service Worker、`/capture` 路由与分享收件箱；静态壳包含构建后的 JS/CSS，API 与令牌不进入缓存。
- 移动导航补充可访问名称，捕获页复用快速笔记 API 并展示最近记录；提醒面板增加显式通知授权、到期集合去重与失败反馈。
- `web/e2e/m10.spec.ts` 覆盖 8 项专项验收；生产 preview 验证 Service Worker 受控、JS/CSS 预缓存、无 API 缓存与 390×844 离线重载零控制台错误。Obsidian 1.15.1 打开同一导出文件，`tags=工作` 与 `collections=M10 验收` 显示为属性，正文与手动编辑均保留。

## 8. 风险与决策规则

- **本地文件访问。** 服务端不直接读用户目录；先用 CLI + 操作系统计划任务，避免容器挂载路径和权限问题。若以后做常驻监听，再评估文件监视与去抖。
- **调度可靠性。** 进程不常驻时定时任务不会执行；首版明确“应用运行时生效”，提供常驻/开机启动说明，不承诺后台服务级 SLA。
- **通知范围。** 先做应用内，避免邮件/推送带来的第三方数据与合规承诺；移动推送放到 M10 并单独披露。
- **中文检索。** PostgreSQL 默认分词不适合中文；优先 `pg_trgm` trigram，SQLite 用 FTS5 trigram，保留 `LIKE` 回退。若扩展不可用，不强行上线索引。
- **语义检索成本。** 向量化需要额外调用与存储；只有固定查询集证明关键词/trigram 不足时才引入，并先做成本上限。
- **Obsidian 写入。** 只做经用户选择目录的显式写入；冲突默认保留，不静默覆盖；双向同步不在本计划内。
- **托管多用户。** 没有环境、预算与运维责任人时保持单人本地，不把模板当成已完成部署。
- **桌面工具链。** 本机已具备 Rust 1.100、Node 24、PyInstaller 6.22 与 WebView2，版本由 `Cargo.lock`、`uv.lock` 与 `web/package-lock.json` 锁定。若未来 Tauri 在签名或 WebView2 上形成硬阻塞，回退 Electron。
- **桌面分发。** 未签名的安装包与自动更新不可公开分发；升级前必须备份数据库，失败可恢复。
- **Web/桌面分叉。** 共用同一套 UI、API 契约与测试；桌面差异只放在运行时适配层。
- **停止规则。** 若一项功能没有降低可测量的摩擦（导入次数、复盘完成率、找回时间、失败率），不继续扩大范围。

## 9. 明确非目标

- 人脸识别、敏感特质推断、医疗/法律/财务决策。
- 常驻麦克风、摄像头、屏幕或设备监控。
- 静默修改原始文件或 Obsidian Vault。
- 面向组织的全量导入与团队知识共享（当前范围）。
- 未经验证的真实用户私测、托管多用户上线与付费运营。
