# 最终产品差距与开发方案

**评估日期：** 2026-11-25  
**评估基线：** 当前工作区（含 M5 统一检索）  
**口径：** 以仓库文档写明的设想为准，不把明确非目标算作待办。本文的能力清单由 PRD、开发方案、里程碑、支持矩阵、架构与入门任务整理而成；状态按可观察实现、测试和验收记录判定。

## 1. 结论

- **MVP 的本地主链已基本完成。** 导入、时间线、照片 OCR、周复盘、提醒、导出、删除、备份恢复、统一检索都有实现和合成验收。
- **按文档设想整理的 51 项能力：26 项完成、10 项部分完成、13 项未开始、2 项为当前范围明确非目标。** 剔除 2 项非目标后，按“完成 1、部分 0.5”加权约 **63%**。
- **Windows 桌面是新增交付形态，当前 0/9 项桌面能力。** 若把桌面交付纳入同一清单，整体完成度约 **53%**；桌面架构与 D0–D4 计划见 [Windows 桌面端架构](../architecture/desktop.md)。
- **PRD P0 的本地功能已覆盖；P1 约完成 50%。** P1 五项中，统一检索和定时复盘/计划同步已交付，模型适配为环境变量级部分实现，更多连接器和移动捕获/通知仍未开始。
- **最大的差距不在“能不能用”，而在“是否省心、是否连得上、是否找得到、是否带得走”。** 依次是：自动捕获与定时复盘、连接器、检索相关性、笔记/标签组织、模型选择与成本可见性、Obsidian/移动端、托管多用户。
- **建议下一迭代做 M7：连接器与快速捕获。** M6 已完成；它直接兑现“降低重复劳动”的核心承诺，下一项应扩大可捕获的资料类型。

## 2. 评估口径

### 2.1 目标基线

“最终产品”分为三层，本文以第二层为主要评分对象：

1. **MVP（P0）**：单人本地可用的导入、时间线、复盘、提醒、导出、数据控制。当前视为完成。
2. **文档设想的完整产品（P1 与后续候选）**：定时同步/复盘、更多连接器、增强检索、可配置模型、移动捕获与通知，以及全文/向量检索、笔记与标签、跨周期洞察、直接 Obsidian 写入、托管多用户等。
3. **超出当前文档的扩展**：AI 对话式问答、团队共享、插件生态、国际化等。本文只列为远期方向，不计入主评分。

### 2.2 状态定义

- **完成**：有实现、测试或验收记录，用户入口可用。
- **部分**：有可用的子集，但缺少文档承诺的关键部分。
- **未开始**：没有实现或只有模板/文档。
- **非目标/暂缓**：当前单人本地范围明确不追求，或文档列为永久非目标。

### 2.3 量化方法

按能力项计数，不以代码行数或页面数量代替。完成度 =（完成项 + 0.5 × 部分项）/ 可适用项。该数字用于排序和沟通，不是精确的工程度量。

## 6. 开发方案

### 6.1 原则

- **单人本地优先。** 不为未见过的多用户需求增加托管复杂度；托管路径保留但不上线。
- **每次迭代交付一个端到端闭环。** 不做只有后端或只有界面的半成品。
- **不改变数据控制不变量。** 所有者隔离、删除不可复活、来源引用可追溯、外部调用需同意与预算，必须随每个功能补测。
- **先测量再扩容。** 检索用固定查询集，性能用固定数据规模，AI 用固定评估集；没有证据就不引入新基础设施。
- **不新增依赖，除非现有栈无法完成。** 优先复用 SQLAlchemy、worker、现有模型网关。

### 6.2 迭代顺序

```text
M6 自动复盘与提醒闭环（已完成）
  ├─ M7 连接器与快速捕获
  │    └─ M8 检索质量与知识组织
  │         └─ M9 复盘智能与模型选择
  │              └─ M10 Obsidian 与移动捕获
  │                   └─ M11 托管多用户（可选，范围变更才启动）
  └─ D0 桌面可行性（与 M6 设计并行）
       └─ D1 桌面 MVP（M6 之后）
            └─ D2 Windows 集成（与 M7/M10 对齐）
                 └─ D3 发布工程
                      └─ D4 可选增强
```

M7 与 M8 的后端部分可在 M6 后并行准备，但按单人维护成本，建议顺序交付。D0 必须与 M6 设计并行，先验证通知、常驻与文件授权，避免先做出仅浏览器可用的调度。

### 6.3 M6 自动复盘与提醒闭环（已完成）

**状态：** 2026-11-25 已完成。Ruff、68 项 Python 测试（含 7 项计划回归）、空库迁移、Web lint/构建与 2 项 Playwright 均通过；执行记录见 [next-iteration 第 7 节](next-iteration.md#7-m6-自动复盘与提醒闭环已完成)。

**目标：** 把“手动导入、手动生成、自己记得”变成“按计划捕获、到期可见”。

**交付：**

1. **复盘计划模型与接口。** 新增 `review_schedules`：所有者、星期、当地时间、时区、是否外部模型、启用状态、上次/下次运行时间。提供 `GET/PUT /api/v1/review-schedule`。时区以用户配置为准。
2. **定时生成。** 复用现有 worker，增加周期性检查：到期时生成上一周期复盘草稿；用 `Review` 的周期唯一约束保证幂等；撤权、暂停、预算不足或未同意时回退模板或跳过，并记录可见状态。
3. **应用内到期视图。** 侧边栏显示到期提醒徽标；Weekly review 页增加“Due now”区；复盘草稿生成后显示“本周复盘已就绪”。先不做邮件/推送，避免新增外部通道与隐私承诺。
4. **计划同步封装。** 现有 CLI `lifeos sync <path> --yes` 已能复用来源并按哈希去重；补充 Windows Task Scheduler 的注册脚本与文档，明确网络失败、路径不存在、来源撤权时的退出码与日志。服务端不读取用户本地路径。
5. **测试。** 覆盖时区边界、同一周期只生成一次、停用计划、撤权/暂停、预算回退、到期提醒分类；补一项 Playwright 设置计划并看到徽标/“Due now”。
6. **文档。** 支持矩阵、部署指南、隐私说明、里程碑与迭代记录；明确“应用内通知，不含邮件/推送”。

**验收：**
- `uv run pytest -q` 通过，新增测试覆盖上述分支。
- 同一周期重复调度不产生第二条复盘；撤权后不再生成。
- Web 可设置/关闭计划，到期提醒与“复盘已就绪”可见。
- 计划同步脚本可按文档注册并幂等运行，重复执行不产生重复条目。
- `npm run lint`、`npm run build`、`npm run test:e2e` 通过。

**依赖与风险：**
- 依赖现有 worker、Review、Reminder、模型同意与预算逻辑。
- 进程必须运行；桌面端需说明开机启动或常驻方式。首版只承诺“应用运行时生效”。
- 定时生成与手动生成可能竞争；用周期唯一约束和状态转换测试覆盖。

### 6.4 M7 连接器与快速捕获

**目标：** 减少手工复制，先接通一个高价值、无外部密钥的来源。

**交付：**
- **日历 ICS 连接器。** 新来源 `calendar_ics`，本地选文件；解析 VEVENT 的 UID、开始/结束、标题、描述、地点；保留时区与来源定位；按 UID + 时间 + 序号去重；支持预览、增量重传、删除与导出。首版只处理单次日程，重复规则明确标注为待支持。
- **快速笔记。** Web 增加“Add note”入口，写入用户自有笔记（`MemoryRecord` 或新的 `quick_note` 来源），可编辑、搜索、导出、删除；与照片描述共用来源引用与删除规则。
- **支持矩阵与隐私。** 新增连接器披露字段、限制和删除行为。
- **测试。** ICS 时区/重复导入/删除、快速笔记的检索与导出、所有者隔离；浏览器用例覆盖导入与编辑。

**验收：** 同一 ICS 重复导入无重复条目；日程进入时间线并能被统一检索；快速笔记可编辑、导出、删除；无外部网络调用。

### 6.5 M8 检索质量与知识组织

**目标：** 从“能找到子串”升级为“先找到相关的那条”，并让用户能组织自己的知识。

**交付：**
- **相关性索引。** 在 SQLite 使用 FTS5 trigram、PostgreSQL 使用 `pg_trgm` GIN（若扩展不可用则回退现有 `LIKE`）；保留统一检索接口与回退路径；增加迁移、升级测试与索引重建命令。
- **筛选与保存检索。** 统一检索增加类型、日期、来源、状态筛选；保存常用查询。
- **笔记与标签。** 为时间线条目/笔记增加标签与集合；Web 可创建、编辑、筛选；导出包含标签。
- **评测。** 扩展现有 22 条查询，比较 `LIKE` 与 trigram/FTS 的 hit@5、P95 和删除一致性；用同一数据规模复测。

**验收：** 检索 hit@5 不低于基线且 P95 ≤500 ms；删除后索引不可召回；SQLite 与 PostgreSQL 迁移均通过；标签/笔记可检索、导出、删除；无跨所有者结果。

### 6.6 M9 复盘智能与模型选择

**目标：** 让复盘更有洞察，并让模型选择与成本可控。

**交付：**
- **提供方/模型注册表。** 支持多个 OpenAI 兼容端点、每提供方同意与价格、复盘时选择模型；可选本地 Ollama 端点；密钥只从环境/本地配置读取，不写入数据库明文。
- **成本与用量面板。** 按用途/周期汇总 token、耗时、估算成本与失败预留；达到预算时回退模板。
- **复盘洞察。** 跨周期趋势、承诺与到期日提取、目标/OKR 关联、复盘版本对比；所有生成事实继续带来源引用。
- **真实语义评估。** 固定 30+ 场景的多提供方评估，记录引用支持率、无据断言、延迟与成本；结果写入迭代记录。

**验收：** 切换提供方需重新同意；预算内生成；评估结果可复现；成本面板与归档一致；无正文日志。

### 6.7 M10 Obsidian 与移动捕获

**目标：** 打通“带得走”和“随时记”。

**交付：**
- **直接写 Vault。** Web 在支持的浏览器使用 File System Access API 选择 Vault 目录，写入带 frontmatter 的 Markdown；冲突时 keep/copy/overwrite 明确选择；不支持时回退下载。发布 frontmatter 字段与标签语义。
- **移动/PWA。** 增加 manifest、分享目标与移动友好捕获页；应用内到期提醒在移动布局可见；浏览器通知需显式授权，失败不影响主流程。
- **测试。** 冲突写入、标签字段、移动视口、分享目标、无权限回退；不静默覆盖。

**验收：** 导出文件在 Obsidian 中正常打开；用户手改后重复导出保留修改；移动端可完成一次捕获与查看；无静默覆盖。

### 6.8 M11 托管多用户（可选）

**触发条件：** 维护者明确改变“只服务本人”的范围，并提供域名、私有 PostgreSQL/S3、预算与运维责任。

**内容：** B1–B3 托管门禁、多用户隔离与邀请、团队空间/共享、审计日志、保留自动化、告警与回滚。该迭代不在当前计划内，不投入实现。

### 6.9 Windows 桌面并行轨道（D0–D4）

桌面端不是 Web 的简单打包：它需要进程管理、Windows 集成、签名安装与更新。完整架构见 [Windows 桌面端架构](../architecture/desktop.md)，决策见 [ADR 0002](../architecture/decisions/0002-windows-desktop-shell.md)。

| 阶段 | 目标 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| D0 可行性验证 | 证明 Tauri + Python sidecar 可打包运行 | Rust/PyInstaller 构建链、最小窗口、sidecar、健康检查、未签名安装包 | 干净 Windows 可启动、导入一条合成资料、退出无残留 |
| D1 桌面 MVP | 现有流程离线可用 | 登录、导入、时间线、检索、复盘、提醒、导出、备份/恢复、日志、凭据存储 | 不装 Docker 完成主流程；重启数据保留 |
| D2 Windows 集成 | 让桌面“像桌面” | 托盘、通知、开机启动、单实例、文件代理、直接写 Vault；接入 M6 调度与提醒 | 提醒可点击回记录；文件夹授权可撤销 |
| D3 发布工程 | 可安全分发 | 代码签名、自动更新、NSIS/MSI、升级回滚、Windows CI、支持矩阵、隐私说明 | 签名安装与升级通过；失败可恢复 |
| D4 可选增强 | 降低依赖 | 本地模型、Windows OCR 备选、ARM64、便携模式 | 按证据单独评估 |

**顺序：** D0 与 M6 设计并行；D1 在 M6 之后；D2 与 M7/M10 对齐；D3 在任何公开下载之前完成。M11 托管多用户与桌面轨道相互独立。

## 8. 风险与决策规则

- **本地文件访问。** 服务端不直接读用户目录；先用 CLI + 操作系统计划任务，避免容器挂载路径和权限问题。若以后做常驻监听，再评估文件监视与去抖。
- **调度可靠性。** 进程不常驻时定时任务不会执行；首版明确“应用运行时生效”，提供常驻/开机启动说明，不承诺后台服务级 SLA。
- **通知范围。** 先做应用内，避免邮件/推送带来的第三方数据与合规承诺；移动推送放到 M10 并单独披露。
- **中文检索。** PostgreSQL 默认分词不适合中文；优先 `pg_trgm` trigram，SQLite 用 FTS5 trigram，保留 `LIKE` 回退。若扩展不可用，不强行上线索引。
- **语义检索成本。** 向量化需要额外调用与存储；只有固定查询集证明关键词/trigram 不足时才引入，并先做成本上限。
- **Obsidian 写入。** 只做经用户选择目录的显式写入；冲突默认保留，不静默覆盖；双向同步不在本计划内。
- **托管多用户。** 没有环境、预算与运维责任人时保持单人本地，不把模板当成已完成部署。
- **桌面工具链。** 当前机器有 Node 24 与 WebView2，但未安装 Rust、Cargo 与 PyInstaller；D0 必须先补齐并锁定版本。若 Tauri 在签名或 WebView2 上形成硬阻塞，回退 Electron。
- **桌面分发。** 未签名的安装包与自动更新不可公开分发；升级前必须备份数据库，失败可恢复。
- **Web/桌面分叉。** 共用同一套 UI、API 契约与测试；桌面差异只放在运行时适配层。
- **停止规则。** 若一项功能没有降低可测量的摩擦（导入次数、复盘完成率、找回时间、失败率），不继续扩大范围。

## 9. 明确非目标

- 人脸识别、敏感特质推断、医疗/法律/财务决策。
- 常驻麦克风、摄像头、屏幕或设备监控。
- 静默修改原始文件或 Obsidian Vault。
- 面向组织的全量导入与团队知识共享（当前范围）。
- 未经验证的真实用户私测、托管多用户上线与付费运营。
