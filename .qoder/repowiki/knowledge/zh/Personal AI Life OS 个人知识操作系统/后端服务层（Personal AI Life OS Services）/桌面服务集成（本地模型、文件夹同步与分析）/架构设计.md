本模块由四个相互独立的 Python 包组成，均位于 `personal_ai_life_os/services/` 下，统一面向桌面版 Life OS 的工作空间数据：

- `desktop_provider.py`：定义 `DesktopProviderSettings`（基于 Pydantic）及 `DesktopProviderStore`，通过 `win32cred`（Windows Credential Manager）在注册表或凭据存储中保存 API Key，并以 JSON 文件持久化 base_url / model / budget 等配置；激活条件强制要求非 loopback URL 必须带密钥，否则禁用该 provider。
- `desktop_folders.py`：实现 `DesktopFolderSync` 轮询已授权的 Markdown 目录与 Obsidian vault，过滤 `.git/.obsidian/$recycle.bin/system volume information/lifeos-exports` 等排除目录，禁止符号链接与重解析点（`FILE_ATTRIBUTE_REPARSE_POINT`），使用 SHA-256 + mtime/dev/ino 做指纹；通过 `ingest_file` 将精选的 chat conversations.json 导出后入库，并通过 `graph_evidence.mark_item_evidence_unavailable` 标记被超时的旧 item。
- `desktop_analysis.py`：作为 Job Worker，调用 `resolve_model_provider('desktop')`，以固定 PROMPT_VERSION 和 OUTPUT_TOKENS=800 发起 JSON Object 请求，产出最多 3 条 kind ∈ {experience, knowledge, action} 的草稿，并校验 quote 必须在原文中出现、confidence ∈ [0.75, 1]；每次调用前按 provider 单价计算 `model_monthly_budget_usd`、`model_max_cost_per_call_usd` 与 `monthly_spend` 限额，写入 `ModelRun` 并按披露版本重新校验 consent。
- `desktop_backup.py`：提供周期性备份（`DesktopBackup.run` 每 60 秒）与离线恢复流程，快照 `data/lifeos.db` 及 `objects/` 中的对象，按前缀 `LifeOS-{hash}-YYYYMMDDTHHMMSSZZ.zip` 保留最近 7 份，并通过 `_absolute_object` 防御路径穿越；恢复时进入 `restore-stage` 目录，清理来源方隐私同意，取消后台任务并标记受 desktop_folders 影响的 source_connections 为 paused。

依赖方向：analysis → desktop_provider（读取 provider 配置）+ jobs/model_consent；folders → ingestion/graph_evidence；backup 独立。各组件均以 `threading.RLock` 保护并发访问共享状态。
