# v0.5 证据图谱个人问答 Spec

## 1. 背景与目标

Personal AI Life OS 当前是单人本地、Web 优先的导入/时间线/复盘/提醒/检索产品。下一阶段不再只做“可检索的记录”，而是做**证据驱动的长期记忆与个人问答**：

- 从聊天导出、本地笔记与文档中抽取人物、项目、目标、任务、主题、技能与成长证据。
- 以可追溯的图谱组织长期记忆，而不是只存向量或摘要。
- 用中文优先的 Chat + 结构化卡片回答“我做过什么决定”“这个项目进展如何”“我在学什么”“某段时间发生了什么”。
- 允许 Agent 在明确边界内自动行动：创建复盘的草稿、提醒、任务、项目与目标进度，但高风险行为永远需要人工批准。
- 为后续连接器与 Agent 插件建立统一协议。

v0.5 不追求多设备同步、手机端和 Windows 桌面；先把 Web 主链、证据质量与成本边界跑通。

## 2. 用户与核心场景

**用户：** 单一维护者，中文优先，使用 Windows 本机与浏览器，愿意用云端模型但要求来源级授权与预算控制。

**v0.5 必须支持的四个问题类型：**

1. **决定/承诺**：我和某人约定了什么？当时为什么这么决定？证据在哪？
2. **项目/目标进度**：这个项目的目标是什么？现在进展如何？下一步是什么？
3. **主题/技能成长**：我在学什么？有哪些证据？技能缺口在哪？
4. **时间线回顾**：上周/上个月发生了什么？哪些事件值得复盘？

**核心体验：**

```text
导入/选择资料 → 手动选择条目抽取 → 低置信度内联待审
  → 证据图谱 → 提问（记住上次范围）→ Chat + 结构化卡片
  → 引用原文/置信度/不确定性/行动建议 → 可选创建提醒/任务/目标进度
```

## 3. v0.5 范围

### 3.1 包含

- Web 中文优先界面；新增图谱、提问、待审、项目/目标、规则洞察与插件设置入口。
- 输入：
  - ChatGPT、Claude、Gemini 导出（JSON/JSONL 或 Markdown）。
  - ZCode、DeepSeek harness、WorkBuddy 的 JSON/JSONL 与 Markdown/文本，先按通用格式解析。
  - 本地 Markdown/Obsidian、TXT、文本型 PDF/DOCX（本地文本提取，不做扫描件 OCR）。
- 图谱：
  - 固定核心本体 + 模型提议、人工批准的自定义类型/关系。
  - 首批实体域：项目/目标/任务；主题/技能/成长。人物与事件作为支撑实体。
  - 证据链接：每个实体/关系可回到原文片段、来源、时间与定位符。
  - 自动合并高置信度实体，支持撤销；低置信度进内联待审。
- 抽取：
  - 手动选择条目后触发；按来源级授权调用云端模型。
  - 多提供方可切换；默认优先低成本模型；批量与缓存。
  - 结构化 JSON 输出校验、失败重试、抽取运行记录与费用记录。
- 问答：
  - Chat + 结构化卡片；记住上次检索范围。
  - 强制原文引用；标注事实/推断/不确定与置信度；附行动建议。
  - 支持追问；问答历史本地保存、可导出、可删除。
- 规则：
  - 目标延期/风险。
  - 承诺到期/未跟进。
  - 项目停滞。
  - 技能证据不足。
- Agent 行动：
  - 可自动创建复盘草稿、提醒、任务/项目、目标进度/成长记录。
  - 每次自动写入通知用户，并提供 24 小时撤销。
  - 高风险红线永远人工批准：对外发送/提交、修改原始文件、花钱/不可逆交易、删除数据/改目标。
- 插件：
  - 同时定义连接器 SDK 与 Agent 工具/权限 SDK。
  - 先提供本地插件清单、权限声明、一个参考连接器与一个参考 Agent 工具。
  - 插件默认无网络、无任意文件访问；越权行为拒绝并审计。

### 3.2 不包含（v0.5 非目标）

- 手机 App、Windows 桌面安装包、系统托盘/通知。
- 多设备同步、CRDT、自建同步服务。
- 完整本体推理、图数据库、向量数据库、实体消歧研究级算法。
- 扫描件 OCR、图片/音频/视频理解。
- 邮件/日历/任务/微信/飞书连接器（留到后续）。
- 插件市场、远程插件执行、第三方插件签名体系。
- 本地数据库加密；v0.5 仅依赖本机账户与磁盘安全。
- 多用户、团队共享、托管服务。

## 4. 功能需求

### FR-1 来源与导入

系统 SHALL 允许用户显式选择聊天导出、Markdown/文本、PDF/DOCX，并记录来源身份、哈希、解析器版本、来源定位与导入时间。

- **场景：重复导入** — WHEN 同一文件再次导入 THEN 不产生重复条目，返回重复计数。
- **场景：自定义来源** — WHEN 导入 ZCode/DeepSeek/WorkBuddy 的通用 JSON 或 Markdown THEN 至少解析出标题、正文、时间（若存在）与来源定位；无法识别时返回可理解错误。
- **场景：PDF/DOCX** — WHEN 导入文本型 PDF/DOCX THEN 本地提取文本并保留页码/段落定位；扫描件明确提示“暂不支持”。

### FR-2 来源级云端授权

系统 SHALL 以来源为单位记录云端抽取授权；只有已授权来源的内容可发送给云端模型。

- **场景：未授权** — WHEN 来源未授权 THEN 抽取只显示“需要授权”，不发送任何内容。
- **场景：撤回来源** — WHEN 用户撤回来源 THEN 该来源标记为不可用；已有图谱实体/关系保留但不再用于问答与规则；证据显示“来源已撤回”。
- **场景：删除来源** — WHEN 用户删除来源 THEN 按现有删除语义清理原件、解析条目与关联证据；图谱中无其他证据支撑的实体/关系标记为失效。

### FR-3 图谱本体

系统 SHALL 维护固定核心本体，并允许模型在抽取时提议新的实体类型或关系类型，经用户批准后加入。

核心实体：

- `project`、`goal`、`task`、`topic`、`skill`、`growth_record`。
- 支撑实体：`person`、`event`、`decision`、`commitment`。

核心关系：

- 项目包含目标/任务；目标有任务/证据；任务属于项目/目标。
- 主题关联项目/技能/事件；技能有成长证据；成长记录引用事件/任务。
- 决定/承诺引用事件、人物、项目；证据指向来源条目。

- **场景：新类型提议** — WHEN 模型提议新类型 THEN 进入待审；批准后可用于后续抽取；拒绝后不再重复提议同一类型。
- **场景：自定义类型** — WHEN 用户批准新类型 THEN 它出现在筛选、抽取提示与图谱展示中，并记录创建者与时间。

### FR-4 抽取流水线

系统 SHALL 支持用户选择一批条目后手动触发抽取。

- 抽取只处理已授权来源的选中条目；生成实体、关系、证据与置信度。
- 输出必须通过 JSON Schema 校验；失败可重试；失败原因可见但不记录正文。
- 抽取运行记录模型、提供方、token、估算成本、耗时、成功/失败数量。
- 高置信度直接入库；低置信度进入待审；阈值可配置，默认从 0.75 开始评估。
- 同一来源条目重复抽取必须幂等或产生可解释的版本，不重复计费。

- **场景：手动触发** — WHEN 用户勾选条目并点击“抽取” THEN 只处理选中的、已授权的条目。
- **场景：预算不足** — WHEN 月度预算达到 80% THEN 提醒；用户可继续或暂停；系统显示剩余额度。
- **场景：模型失败** — WHEN 抽取失败 THEN 运行记录失败原因，条目保持可重试，不写入半成品实体。

### FR-5 实体合并与待审

系统 SHALL 自动合并高置信度的同一实体，并允许撤销；低置信度变更必须进入待审。

- 同一人物/项目通过名称、别名、来源标识与上下文相似度合并。
- 合并保留别名、原始实体、合并时间与操作者；撤销后恢复原状。
- 待审项在导入完成后内联展示；支持批准、拒绝、编辑、合并与批量处理。
- 待审只展示低置信度项；高置信度项可事后编辑。

- **场景：自动合并错误** — WHEN 用户撤销合并 THEN 两个实体恢复独立，证据与关系回滚。
- **场景：内联待审** — WHEN 导入完成 THEN 时间线/图谱结果中显示待审数量入口；不弹窗打断。

### FR-6 个人问答

系统 SHALL 提供中文优先的 Chat + 结构化卡片问答。

- 用户可选择检索范围（来源/项目/主题/时间）；默认记住上次范围，可清空。
- 答案包含：
  - 结构化事实/结论。
  - 原文引用（来源、时间、片段、定位符）。
  - 事实/推断/不确定标记与置信度。
  - 缺失信息与下一步建议。
- 支持追问；问答线程本地保存、可导出 JSON/Markdown、可删除。
- 问答不得使用已撤回来源、已删除条目或已失效证据。
- 默认 30 秒内返回首屏；超时显示进度与可取消。

- **场景：决定问答** — WHEN 问“我和某人约定了什么” THEN 返回承诺、人物、时间、项目、原文引用与置信度。
- **场景：无证据** — WHEN 图谱没有足够证据 THEN 明确回答“没有找到可靠证据”，不编造。
- **场景：范围记忆** — WHEN 下一次提问 THEN 沿用上次范围；用户可一键清除。

### FR-7 规则洞察

系统 SHALL 提供四条可解释规则：

1. 目标延期/风险：目标有截止日期但无进展或已过期。
2. 承诺到期/未跟进：承诺有到期日或长期无后续证据。
3. 项目停滞：项目长期无新证据或状态未更新。
4. 技能证据不足：技能缺少证据或长期未练习。

- 规则输出必须列出触发条件、证据、置信度与建议动作。
- 规则结果进入问答与图谱页面，不单独发外部通知。
- 规则阈值可配置；误报可忽略并记录，避免重复提示。

### FR-8 Agent 行动

系统 SHALL 允许 Agent 在内部自动写入，并支持通知与 24 小时撤销。

允许自动写入：

- 复盘草稿、提醒。
- 任务、项目、项目状态。
- 目标进度、成长记录。

永远需要人工批准：

- 对外发送/提交（邮件、消息、评论、表单）。
- 修改、移动、重命名或删除原始文件。
- 花钱、下单、签约、预订或不可逆交易。
- 删除个人数据、修改目标或长期记忆。

- 每次自动写入产生 `AgentAction` 记录：类型、目标、前后值、证据、模型、时间、可撤销截止。
- 用户收到应用内通知；24 小时内可一键撤销；撤销恢复前后值。
- 红线由工具层强制，不依赖提示词；越权调用被拒绝并审计。

### FR-9 插件 SDK

系统 SHALL 同时提供连接器与 Agent 工具接口。

连接器接口：

- 预览、导入、删除、来源定位、权限声明。
- 只读用户明确选择的路径；默认无网络。

Agent 工具接口：

- 工具名、参数 schema、权限级别、是否需要批准、审计字段。
- 可访问内部图谱/检索、读取授权文件、写文件需批准、外部访问需批准。

- 插件使用本地清单声明权限；未声明权限默认拒绝。
- v0.5 至少提供一个参考连接器（通用 JSON/Markdown）与一个参考 Agent 工具（图谱检索）。
- 插件失败不能破坏主流程；插件操作记录审计日志。

### FR-10 中文优先界面

系统 SHALL 提供中文优先界面，保留英文内容处理能力。

- 导航：时间线、图谱、提问、复盘、项目与目标、待审、设置。
- 图谱页展示实体、关系、证据、置信度与状态。
- 提问页展示 Chat、结构化卡片、范围选择、历史与行动按钮。
- 待审页/内联入口展示低置信度项与合并冲突。
- 设置页包含来源授权、模型提供方、预算、本体自定义、插件、删除/导出。

## 5. 非功能需求

- **证据优先**：任何生成结论必须可回到原文；无证据时明确说明。
- **隐私**：来源级云端授权；撤回来源不可用于问答；日志不写正文；问答历史本地保存。
- **成本**：月度预算 <$5；80% 提醒；默认低成本模型；批量、缓存、去重；记录每次调用成本。
- **性能**：问答首屏 <30 秒；图谱页面分页；1 万条时间线 + 图谱不出现明显卡顿。
- **可靠性**：抽取可重试、幂等；失败不写半成品；插件失败隔离。
- **可解释性**：规则、Agent 行动、插件调用都有审计与证据。
- **可移植性**：图谱、问答历史、来源与证据可导出；不锁定外部服务。
- **安全**：红线由工具层强制；插件默认无网络/文件权限；高风险动作需批准。

## 6. 数据模型（新增）

- `GraphEntity`：owner、type、name、normalized_name、summary、confidence、status（active/merged/invalid）、created_by、timestamps。
- `GraphRelation`：owner、from_entity、to_entity、type、confidence、status、valid_from/valid_to、created_by。
- `GraphEvidence`：owner、entity/relation、source_item、source_id、quote、locator、confidence、availability（active/revoked/deleted）。
- `EntityAlias` / `EntityMergeLog`：别名、合并前后、操作者、可撤销信息。
- `OntologyType`：owner/global、kind（entity/relation）、name、description、status（proposed/approved/rejected）、source（model/user）。
- `ExtractionRun`：owner、source/条目范围、model/provider、status、counts、cost、latency、error_code。
- `GraphReviewItem`：owner、kind、payload、confidence、status、extraction_run。
- `QaThread` / `QaMessage`：owner、scope、question、answer JSON、citations、confidence、timestamps。
- `AgentAction`：owner、kind、target、before/after、evidence、status、approval、expires_at、audit。
- `PluginManifest` / `PluginPermission`：本地插件、权限、启用状态、审计。
- `BudgetUsage`：按 owner/月/用途聚合 token、成本、限额与告警状态。

所有用户数据带 `owner_id`；删除/撤回必须联动证据可用性。

## 7. API 草案

- `POST /api/v1/extractions`：选择条目触发抽取；返回 `ExtractionRun`。
- `GET /api/v1/extractions/{id}`：状态、计数、成本、错误。
- `GET /api/v1/graph/entities`、`GET /api/v1/graph/relations`：分页/筛选/证据展开。
- `GET/POST /api/v1/graph/review`：待审列表、批准/拒绝/编辑/合并。
- `POST /api/v1/graph/entities/{id}/merge`、`POST /api/v1/graph/merges/{id}/undo`。
- `GET/POST /api/v1/ontology/types`：模型提议、批准/拒绝、自定义。
- `POST /api/v1/qa/threads`、`POST /api/v1/qa/threads/{id}/messages`：提问与追问。
- `GET /api/v1/qa/threads`、`DELETE /api/v1/qa/threads/{id}`、导出端点。
- `GET /api/v1/insights/rules`：四条规则结果与证据。
- `GET /api/v1/agent/actions`、`POST /api/v1/agent/actions/{id}/undo`、批准端点。
- `GET/PUT /api/v1/budget`：月度预算与使用。
- `GET/POST /api/v1/plugins`、`POST /api/v1/plugins/{id}/enable`。

## 8. 验收标准

1. **30 条合成问题**覆盖四类问题与中英文；引用正确率 ≥90%；无据断言为 0。
2. 低置信度待审 ≤10 条/周；审核后可撤销。
3. 决定/项目/成长/时间线问题首屏 <30 秒。
4. 同一文件重复导入不重复；重复抽取不重复计费。
5. 未授权来源不发送云端；撤回来源不进入问答；删除来源后无残留可用证据。
6. 预算达到 80% 有提醒；超过预算不静默继续。
7. Agent 自动写入均有通知与 24 小时撤销；四条红线在工具层被拒绝。
8. 参考连接器与参考 Agent 工具可安装、启用、审计与卸载。
9. 中文界面主流程可用；导出包含图谱、问答与证据。
10. 现有 68 项后端测试、Web lint/build、Playwright 用例保持通过。

## 9. 风险与开放问题

- **范围风险**：v0.5 同时包含图谱、规则、Agent、插件，工程量接近平台；必须按阶段验收，不能一次性合并。
- **成本风险**：<$5/月 + 全量抽取 + 云端质量优先可能不成立；需要低成本模型、手动选择条目、缓存与预算硬约束。
- **抽取质量**：实体/关系抽取与合并容易出错；低置信度待审与撤销是必要安全阀。
- **本体治理**：自定义类型需要版本、迁移与废弃策略；否则图谱会碎片化。
- **插件安全**：本地插件仍可能越权；v0.5 只做权限声明与审计，不做强沙箱。
- **无加密**：v0.5 仅本机；未来同步前必须补加密与密钥管理。
- **开放问题**：默认模型提供方与路由；自定义来源的最终字段；中文/英文混合问题的评测口径；图谱页面信息密度。
